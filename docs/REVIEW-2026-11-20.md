This review uses source inspection, deterministic execution and browser scenarios; no new paid/model calls were made. Existing untracked `output/ux/` designs were preserved.

## Result

Keep the TypeScript modular monolith and Cordis composition. The core/adapters/protocol/client split is functioning and covered by contracts. Buro owns dispatch, scope, checks and acceptance. Provider transports share one managed loop; raw continuation and credentials stay private. Replacing the workflow framework or moving to services is not justified by the observed problems.

The next release risk is aggregation and lifecycle semantics: session limits are not a goal budget, short steps are not complete agents, and fresh context alone does not repair incorrect code. Implement a durable managed-run budget before enabling automatic work segments. Real-project quality remains an open gate.

## Preserve these boundaries

- Core decisions use injected ports; Cordis remains in composition, Node/process/Git/provider details in adapters.
- Frozen role/resource/policy snapshots remain authoritative; later role edits do not retarget dispatched work.
- Persist intent/reservations before effects; retain unknown outcomes and never replay them automatically.
- Scope and protected checks remain enforced independently of model summaries.
- Context projection remains separate from private durable history and provider continuation.
- Private prompts, raw tool arguments, credentials and provider state stay outside public budget summaries/events.
- Original example project code/metadata stays read-only; use bounded copies and synthetic data for evaluation.

## Connection follow-up

R8's held-session dependency is removed: RTX inference now uses a direct private-network HTTP API with a separate Windows startup task and a firewall restricted to the Mac. No password is stored, and Buro has no SSH lifecycle dependency. Endpoint settings are editable through the shared command/UI with explicit restart application, optimistic concurrency and private-network trust. Existing owned runs retain active providers; changed historical routes fail closed after restart. Continuous health monitoring, automatic retarget/recovery and dynamic configuration generations are not implemented.
