## Failures and repair

The Qwen code-style session received HTTP 200 and then a native Ollama generation error. Windows engine logs at `2026-11-26T00:05:45+03:00` recorded a tool-call parsing failure: `XML syntax error on line 3: unexpected EOF`. Other native calls succeeded. This establishes a native parsing failure, not lack of function-calling support, and does not distinguish malformed generation from a parser defect. No application-side tool parser was introduced.

The Flash code-style report contained a naming observation, but its JSON finding used `issue`/`file` rather than the required `message`/`path`. The generic JSON instruction transport had not delivered the schema at all. Commit `f992728` fixes schema delivery for instruction transports, while native JSON-schema transports retain their existing wire contract. The original benchmark remains frozen.

Four real API contract probes validated after that fix. The first pair used full saved public history directly; the medium request was therefore much larger than the original bounded request. Those are unbounded diagnostics, not matched comparisons. A second pair uses the ordinary nominal 32K public-history context builder. Neither pair replays private adapter continuations or constitutes a full correction cycle. All four calls remain in the diagnostic ledger: $0.023708856 total, separate from the original cases. The reported naming and test-double suggestions are minor review opinions, not independently demonstrated functional defects.

The product fix passed lint, formatting, type checks, 131 repository tests and a production build. Its contract regression test covers instruction, JSON-object and native JSON-schema modes without mutating saved conversation history or converting text to tool calls.

## Context-budget repair and native validation

Late MiMo requests repeatedly reported approximately 32K input plus only 500–700 generated tokens before reaching the 32K total, despite an 8K configured output allowance. The old four-character input estimate did not reserve that output space in the actual tokenizer. Request projection now measures UTF-8 bytes, accounts for tool/schema overhead and raises its token-density estimate from actual prompt usage, scoped to each model/backend revision within the turn. Only backends declaring prompt-scoped usage participate; aggregate native-agent counters remain separate. History is not rewritten; whole tool exchanges and private continuation remain associated correctly. The estimate can still be inaccurate for unseen input distributions or missing usage; no model-specific workaround or exact-tokenizer guarantee is claimed.

The generic fix passed lint, formatting, types, 135 tests and production build. A regression model with dense byte-tokenized input demonstrates feedback-based output reservation while retaining full saved logs. Additional regressions cover multibyte text, complete tool exchanges and exclusion of aggregate native-agent usage.

On the same saved interrupted MiMo history, the old projection produced 31,096 native input tokens, leaving 1,672 in a 32,768-token window. The calibrated projection produced 23,219, leaving 9,549 for the configured 8,192 output allowance. Both input-size diagnostics generated at most one token and executed no proposed tools. They are not exact historical wire replays or end-to-end reruns. The first calibrated attempt failed with a network read timeout; a direct native retry returned the measured count. Streaming mode, cache/loading state and request sizes differ, so wall times are not a model-speed comparison. The prior inference server was restored. A completed quality rerun after this repair remains outstanding.
