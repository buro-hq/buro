The same real service scenarios run against both adapters. A test registry deliberately throws on legacy snapshot/document transaction/receipt/list calls, so the use cases must consume `.entities`. Goal cases cover initial draft/revision, exact request replay without rerunning ID/clock callbacks, stale CAS, detached reads, known inactive material references, omitted-versus-explicitly-empty attachments, deletion and replay without resurrection. Role cases preserve exact user instructions, fixed/preferred/automatic selection semantics, generated workflow/template lineage and original creation time. Concurrent saves with one expected version have one winner; old versions remain immutable and readable after reopen.

Parent-reference cases reject missing runs, completed references without commits and failed references with commits. Only a stored completed reference with a saved commit is accepted as a parent. An older busy result behind 1,000 later history records still blocks deletion for pending delivery and running preview; settling it permits deletion despite the retained completed history. SQLite performs the actual indexed busy query, not a scan of a UI page.

SQL-specific cases create goal, role, account and generation admission in one transaction. Rollback removes every entity/account/operation/event/receipt; a successful retry survives reopen. Entity and usage facets share the same receipt namespace and one ordered event sequence. A guarded temporary SQLite trigger fails role-head insertion after the role-version insert. Even when the callback catches that physical error, the transaction rejects and leaves no orphan role, goal, usage charge, event or command receipt. Removing the test trigger allows the same command to succeed exactly once.

File fixtures use the existing trusted document-seeding mechanism. SQLite fixtures seed only material/run-reference indexes in an explicitly marked temporary database because their production writers are not implemented yet. The separate trigger is a test-only physical storage fault. These fixtures establish reference/busy lookup facts; they do not invent a production accepted-Run API or prove code acceptance. No model, RTX endpoint, credential or original user repository was used.
