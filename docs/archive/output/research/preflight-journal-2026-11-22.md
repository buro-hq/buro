# Runtime/session/effect preflight after 233bcc8

Date: 2026-11-22. Read-only production review for the next Run/journal implementation. This report adds no production or test code. File remains the sole production authority; SQL v8 is a separately tested authority, not the live runtime. RTX, live models, original projects and output/ux were not accessed.

## Findings, in priority order

1. **Confirmed observation boundary gap: deduplication does not survive a recreated executor.** `core/execution.ts:2041` resolves an event by scanning project snapshots, then `:2052` checks only an in-memory `(runId,event.id)` Set. The receipt is not part of the persisted transaction. A synthetic probe using real FileProjectStore and genuine Goal/queue/begin/phase/bind commands delivered the same message event twice to one ExecutionService: one persisted message. Recreating ExecutionService over the same live store and redelivering the identical event produced a second message and revision. This reproduces non-durable deduplication; it does not prove that a real provider/native transport automatically redelivers after a process restart. There is no automatic replay contract currently supplying that guarantee. `:2058` correctly records the in-memory key only after success, so an ordinary failed write can be retried; preserve that property.

2. **Confirmed observation boundary gap: current acquired attempt ownership does not establish the source event's ownership.** The same probe genuinely stopped the initial attempt, resumed a distinct attempt and began it. With `executionOwners` set to the new acquired attempt, a message event carrying a predecessor-named synthetic thread was still persisted in the current Run. `observe` supplies no expected source attempt; `update` at `core/execution.ts:936` instead captures the current executor's owner. `core/runtime-events.ts:2` has only Run/thread/event IDs, and `core/runtime-router.ts:695` validates Run identity while relay `:713` normalizes the resource/route/event IDs. It does not bind an observation to a dispatch/turn/attempt epoch. Historical events must remain retrievable, but their source cannot implicitly grant current worker completion or assignment authority. The probe calls `observe` directly, without a real native process/router stream and without reproducing incorrect acceptance or skipped worker execution. Treat source ownership as the proven boundary omission and those downstream consequences as risks requiring regression tests. Router cleanup limits the real transport exposure: `core/runtime-router.ts:675` retains its acquired lease/mappings while adapter release is pending; only after successful release does `:682` delete route/native/child relay mappings. A completed release therefore prevents ordinary relay through those mappings, and an existing test covers released child events. The Core probe does not bypass that distinction to claim a real post-release replay. Pending release, queued observations and explicit later resume still need source-epoch tests; persisted routes themselves are not deleted by release.

3. **Planned reliability gap: effect/accounting/session updates remain separate commits.** `core/managed-host-effects.ts:57` reserves usage in the project ledger, `:83` persists generation intent in the private session, `:91` calls the provider, `:118` retains its normalized response, `:127` settles usage, then `:195` appends messages/tool intents. The observed response is deliberately durable before usage settlement or tools. Existing tests prove that a usage failure retains the response and prevents tool dispatch; this is a useful guarantee, not atomicity across the two owners. A process loss between these steps still requires explicit recovery ownership and settlement from retained evidence. Never answer it by repeating the provider or by inventing zero usage. `adapters/files/project-run-budgets.ts:25` still uses the sole project document ledger; `adapters/files/managed-sessions.ts:765` independently rewrites the private whole-session checkpoint.

4. **Planned reliability gap: native start and resume do not share a transactional effect owner with current attempt state.** `core/runtime-router.ts:353` saves a starting route before external start `:363`, then saves the external reference/ready state `:364`. `:373` conservatively records unknown on failure and `:620` rejects resuming a non-ready route. This prevents a known unknown start from silently becoming a fresh session. However, current state and route grant are separate authorities, routes have no attempt epoch (`adapters/files/runtime-routes.ts:13`), and external resume at `core/runtime-router.ts:585` has no distinct persisted resume-effect receipt. A crash after acquiring a native session but before its handle is committed can leave an orphan; no crash-orphan/process lease proof is claimed. Source inspection identifies these windows; this review did not simulate process death there.

5. **Default-none remains blocked by real storage/lifetime contracts.** `core/model-ports.ts:38` retains scope revisions, turn authorities, actions, messages and segment archives in a ManagedSession aggregate. `adapters/files/managed-sessions.ts:767` clones, validates and serializes that whole object for each save. Context rotation keeps an active window bounded but archives full prior windows in the same checkpoint (`core/managed-coding-context.ts:234`). Lifetime session requests remain checked at `core/managed-loop-host.ts:76`; per-turn limits at `:74` and `core/managed-host-effects.ts:183`; segment/feedback stops at `core/managed-worker-checks.ts:156`. Removing these counters now would permit growth rather than implement the intended persistent unbounded history. Retain physical request/context bounds while distinguishing optional user quotas from hidden lifetime stops in the later policy cutover.

## Next coherent implementation order

1. Finish current worker task/assignment revision authority, including the actual known-failure refinement writer and current dispatch reader. Its grants will be referenced by subsequent sessions; do not make the original immutable accepted task pretend to be a current refined task.
2. Add actual runtime observation ownership/deduplication as a Run consumer: named project/Run/session/dispatch-epoch lookup, source event receipt and its semantic observation/timeline/public event in one transaction. Duplicate replay after reopen publishes nothing; failed commit permits exact redelivery. Delayed predecessor events are either historical observations or rejected current-state changes. Undeclared native children remain visible without assignment grants. Source IDs must be stable across transport reload; a fresh event ID is not deduplication.
3. Move actual native routes and managed session/turn/scope/effect/usage owners into the same authority, preserving existing ordering/once gates and acquired adapter cleanup. Use narrow known-record commands and indexed named reads, never a method that reconstructs all historical Run/session state. Each observed normalized response, usage settlement and whole proposed action batch needs atomic commit; each external command retains its own intent/outcome. Unknown stays an indexed unresolved owner until explicitly reconciled.
4. Store complete private outputs/messages/artifacts incrementally and page their history with a replay/live handoff; keep active model context bounded. Migrate research/environment/delivery callers too, not only coding sessions. Then complete genuine acceptance/result/application authority and remove old production aggregate writers before SQL cutover. Only afterward remove audited lifetime defaults coherently.

These slices follow the saved Run/journal contract; they do not introduce a replacement scheduler or generic `putRun`/`putSession` mutation API. Durable deduplication cannot be an unused SQL-only receipt table while the production observation writer remains generic File update. SQL accounting must not be dual-written beside the active File ledger.

## Required adverse proofs

Use actual File/SQL consumers with snapshot/document APIs disabled at the migrated boundary. Cover identical source events after service recreation/reopen, equal event IDs from different sessions, conflicting payload reuse, failed physical commit and redelivery, old events during/after stop/resume/cancel, and historic events beyond the first page. Prove named lookup/query work independent of retained history. For the shared effect owner, inject process-loss boundaries before/after session acquisition, model dispatch/response/usage, complete batch commit, each tool/helper/service-check receipt, context rotation and accepted checkpoint. A retained response is not another provider request; a pending/unknown external command is not an automatic retry.
