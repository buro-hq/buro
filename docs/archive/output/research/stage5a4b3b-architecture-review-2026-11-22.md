## Architecture and boundaries

Actual nonaccepted finish and resume now use required semantic Run authority. Stop cannot manufacture completion/acceptance. Current state, immutable stop, goal linkage, public timeline/change and receipt commit together. Existing unresolved operation markers are retained: stopping unknown work becomes needs-attention, and any unresolved operation of the goal blocks continuation. No unknown operation is automatically replayed or cleared by the new commands.

A continuation captures complete updated goal/criteria/clarification, selected and retained material references, policy/checks, frozen control-role/resource decisions and explicit workspace/plan origin grants. It appends a distinct immutable attempt and moves current ownership atomically. Changed-goal tasks use the complete goal; a reverted goal cannot revive older compact-task authority without a new legitimate plan decision. Successful worker evidence can remain reusable for an unchanged goal. Later worker-task refinement still has its existing owner.

Actual execution captures an attempt identity. Awaited generic updates, phase/bind/plan transitions, stop and acceptance checkpoints compare that owner before mutating a newer attempt. Scheduling retains the old job through cleanup; afterward it dispatches only a genuinely distinct, saved, uncanceled queued attempt, with reconciliation still blocking work. It does not retry the same stopped/unknown attempt merely because a promise settled. These checks are local attempt ownership, not a cross-process external-effect dispatch lease.

File remains the sole production authority and accounting owner. Its temporary Run/history projection is guarded against bypassing the new attempt records; full public history still lives in the aggregate. SQLite stores separate attempt headers, contexts/material/check/role rows and stops in the existing transaction and event/receipt namespace. SQL tests hold scheduling and do not hydrate a Run or invent accepted/session/accounting effects.
