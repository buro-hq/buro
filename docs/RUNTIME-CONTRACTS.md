# Runtime contract evidence

This matrix records deterministic evidence for native Codex and the managed Ollama/DeepSeek routes. Provider HTTP and Codex stdio are fixtures; repository edits, file checkpoints, routing and service checks are real. These tests do not establish live model quality. [Provider acceptance](PROVIDERS.md), [implementation progress](IMPLEMENTATION.md) and the [roadmap](../ROADMAP.md) keep that gate separate.

The cancellation cases assert exact generation/start counts, not just a final failure. Ollama's separate tools-free JSON turn is counted explicitly; it is not a retry of an interrupted request. No contract authorizes a remote fallback for local-only work.

Native cancellation before a start reply closes the owned stdio connection because the native outcome is unknown. It does not claim that remote computation stopped. The saved thread can be explicitly resumed. Managed recovery likewise refuses a pending tool action with an unknown outcome; this matrix does not establish automatic crash reconciliation or exactly-once execution.

Service-owned filesystem and Git boundaries are checked separately in [tool isolation](../tests/tool-isolation.test.ts), [service Git isolation](../tests/service-git-isolation.test.ts) and [local apply](../tests/apply-git-isolation.test.ts). These cover private reads, network policy, hostile Git drivers and symlink ancestors around the model loop.

Run the full deterministic suite with `npm test`. Live Ollama checking is opt-in through `BURO_LIVE_OLLAMA=1 node scripts/check-live-ollama.cjs`; DeepSeek live acceptance requires separately configured credentials. Neither live check belongs to the default suite.

## Managed worker segments

[Managed segment tests](../tests/managed-segments.test.ts) preserve DeepSeek continuation through closure, separate Ollama serialization, stable logical routing, cumulative limits and the unknown-generation/action stop. They exercise invalid/partial closure, duplicate archived action IDs, failed checkpoint, cancellation, previous-specialist reversion and policy mismatch. [Private checkpoint tests](../tests/segment-checkpoints.test.ts) verify atomic archive/active-window persistence, append-only history and receipts, stale-write rejection, restart and malformed archives. [Workspace evidence](../tests/segment-evidence.test.ts) uses real Git worktrees, mode/content fingerprints, protected package fields and hostile Git/symlink cases. [Pure contracts](../tests/work-segments.test.ts) verify that step events never complete the logical worker or accept a result.

Segments apply only to Buro-managed implementation assignments with injected service workspace evidence. Native clients, coordinator and reviewer retain their original conversation lifecycle. A window limit, request limit or unknown response does not authorize another provider or a new budget. An already oversized unresolved tool chain cannot be rescued by dropping it.

The explicit synthetic live gate is `BURO_LIVE_SEGMENTS=1 node scripts/check-live-segments.cjs deepseek` or `mixed`. It pins Mac loopback Ollama/Qwen Instruct and DeepSeek, never selects a user's source case or RTX endpoint, and retains the existing 24-generation / 65,536-reserved-output / five-minute ceiling. Its one-rotation acceptance claim requires both an actual archive and normal service checks/fresh review. These live calls remain outside default tests.
