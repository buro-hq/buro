Дата: 22 ноября 2026. Проверенный код: `233bcc8`. Пять агентов работали двумя волнами: Core/задачи работников, runtime/журнал, границы хранения и пакетов, готовность релиза, независимая проверка следующего среза. Production-код и тесты этим ревью не менялись. RTX выключена, исходные проекты и `output/ux/` сохранены. Сокращённый scope беты не утверждён; требование default-none сохраняется.

## Вывод

Архитектурное направление сохраняем: Core владеет правилами, адаптеры — хранением и внешними действиями, protocol — публичными контрактами. Проверки импортов проходят. Уже перенесены admission/cancel, activation/phase, workspace binding, принятый план с исходными назначениями, остановки и отдельные попытки продолжения. Сохраняются проверки точной ревизии, независимый reviewer и запрет автоматического повтора неизвестного эффекта.

Основной незавершённый блок — единая authority исполнения. Production по-прежнему использует File, а SQL обслуживает только перенесённые узкие use cases. Текущий executor, session/router, research/result/apply и клиенты ещё зависят от целых Run/ManagedSession и растущей истории. Переключать фабрику на SQL или снимать lifetime-лимиты сейчас нельзя: это не завершит согласованный контракт восстановления и ограниченного активного контекста.

## Что осталось до релиза в текущем scope

1. **Текущие worker-задачи и результаты назначений.** Отдельные версии уточнённых задач, указатель текущей версии, реальный producer invocation/outcome/release eligibility. Сохранить исходные criteria/result/role/resource/paths, изменённый goal и уже успешных работников. Убрать выбор текущего результата через всю agent history.
2. **События runtime.** Indexed owner lookup, durable source receipt, привязка к session/dispatch/turn epoch и атомарная запись observation/projection/event. Повтор после reopen ничего не публикует; неуспешный commit разрешает повторную доставку. Старое событие не получает authority новой попытки. Один threadId недостаточен: coordinator намеренно продолжает старый thread.
3. **Сессии, внешние действия и учёт.** Реальные native/managed route/session/turn/scope/model/tool/check/usage writers в одной authority. Полный proposed batch и наблюдённый ответ сохраняются до effects; unknown требует reconciliation. Нужны crash-инъекции вокруг каждого dispatch/settle и сохранение исходного adapter lease для cleanup.
4. **Acceptance, research, результат и применение.** Перенести actual revision-bound evidence/acceptance и существующие prepare/dispatch/settle использования результата. Сохранить свежий review, exact tree/checks/scope, cancellation и защиту Git application от повторного merge. Фальшивый accepted Run для SQL-проверок не допускается.
5. **Полная история и завершение storage/default-none.** Отдельные полные artifacts, bounded active context, paged public/private history и replay/live handoff; решения больше не читают целые истории. После переноса всех потребителей — чистый pre-release SQL cutover без dual write и legacy resume. Затем согласованно убрать скрытые lifetime/default stops, сохранив explicit user quotas, физические/request/context границы. Проверить продолжение за всеми прежними порогами и конечные пользовательские квоты.
6. **Проверка кандидата релиза.** Настоящие Codex, Mac Ollama, DeepSeek на одинаковых временных задачах: полезный edit, rejection/repair, отрицательный acceptance-case, независимый oracle и честный usage. Свежий пользовательский UI/CLI путь, чистая macOS-установка, остановка/forced termination, отсутствие оставшихся owned процессов/портов и корректный restart. Финальные full tests/build/browser/reviews на зафиксированном кандидате. Публикация отдельно не разрешена.

Artifacts, проверенный review packet и подготовку установки можно делать параллельно с persistence. Финальная quality/recovery-проверка нужна на итоговом кандидате. Это шесть групп работ с несколькими самостоятельными коммитами, а не шесть небольших исправлений; календарная оценка по числу тестов необоснованна.

Независимые четыре пакета/второй host, MCP-цели, параллельные goals/resource queues, desktop installer и расширение OS остаются в полном плане. Они не становятся автоматически блокерами первого релиза. Compiled standalone provider consumer уже проверяется; полный package/backend lifecycle ещё не доказан. Ничего из этого не отменяется данным ревью.

## Следующий цельный этап: 5A4b3c

Перенести current task revisions вместе с минимальным настоящим producer worker invocation/outcome/release eligibility и его recovery/dispatch readers. Не ограничиваться таблицей задач с неиспользуемым интерфейсом. Семантические команды проверяют current attempt, lifecycle, task revision, исходный grant и конкретный завершённый outcome; request consumes refinement до coordinator call. Сохранение refinement может сузить inputs и уточнить objective, но не ослабить критерии, expected result, роль, ресурс, checks и write authority.

File остаётся единственным production store/ledger. На SQL этот срез доказывается настоящим Core worker producer с управляемыми runtime/turn/workspace ports и запрещёнными snapshot/generic document APIs на перенесённой границе. Это не полный routed SQL runtime: реальный RuntimeRouter/ManagedRuntime ещё требует session grants из следующего этапа. Не подставлять synthetic failed row и не собирать полный Run ради доказательства.

Exit: actual plan → known failed/released worker → persisted request → accepted revision → fresh worker; неизменные criteria/result, input subset, успешный sibling; changed/reverted goal; late response, stop/cancel, конкурирующие request/save и receipt replay; physical File/SQL rollback; named reads не зависят от старой истории. Процессные crash leases и неизвестные effects остаются следующим gate. После реализации — полный suite, build, релевантные browser checks, независимые architecture/boundary reviews и отдельный коммит.
