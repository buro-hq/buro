The existing product already connects a repository, configures Codex/Ollama/DeepSeek routes, creates goals and roles, dispatches workers, checks an immutable workspace, obtains fresh review and exposes an accepted result. This review changes no production behavior or release scope.

Record semantic result quality, time, usage coverage and failures, with no claim that a model connection probe proves coding quality. Original source projects stay unchanged; the RTX computer remains outside this test scope.
2. Close release-critical stop/restart/retry gaps. Nonaccepted stop/continuation transactions and the resume-during-cleanup race are now covered; this does not complete crash recovery around external effects. Test interruption and process restart around model/tool effects, coordinator/worker sessions, result preparation and application. Unknown external outcomes require explicit reconciliation rather than automatic duplicate dispatch. File storage can remain the active backend for a bounded beta; SQL existence alone does not complete this gate.
3. Make actual finite and physical limits visible and adjustable where supported. Remove misleading stop reasons and expose the next action. Do not advertise unlimited/default-none execution while lifetime/history ceilings remain.
4. Test the fresh-user flow: empty startup, one explicit model/profile, project/check setup, first goal, diff/check/review evidence, intervention and result application. Explain the current service restart needed after connection setup and the authoritative profile/export relationship. Fix functional UX blockers; a full redesign is not a release prerequisite.
5. Validate installation from a clean macOS environment using the documented Node/Git prerequisites and one service/frontend launch command. Confirm cleanup on stop, private local state, credentials handling and documentation. A desktop installer and untested platform claims are unnecessary for a first local beta.

## Default-none release gate

If the first release must include the user's intended no-default-budget behavior, transactional executor/session/effect persistence and bounded active context with complete paged history must land first. Then remove audited lifetime request/tool/turn/segment/repair/material stops coherently, preserve explicit optional user quotas and physical request constraints, and rerun adverse recovery/quality comparisons. Merely lifting numeric caps on the growing File/ManagedSession aggregates is not that implementation.

A bounded beta is an optional narrower release proposal, not an accepted change to this requirement.
