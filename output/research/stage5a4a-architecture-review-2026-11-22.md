## Architecture and simplicity

Core owns actual queue/cancel semantics and preflights the complete goal/profile/role/resource/material/workflow authority before its first mutation. Role resolution reads trusted sealed content without appending versions during validation. A genuine queued Run, immutable admission and initial attempt, goal link, created roles, timeline, public event and command receipt share the same transaction. There is no generic put-Run or accepted-result creation API.

SQLite stores explicit scalar current fields, immutable admission/initial-attempt rows and separate timeline rows. It writes the existing active/unresolved guard index as part of genuine queue/cancel commands. Required owner lookups and frozen cursor pages use indexed scoped queries. An admission is a one-time captured task/grant record, not a growing Run/history JSON column. Queue tests hold the scheduler and cannot operate the unmigrated SQL executor.

File remains the sole active project authority, with the existing managed ledger only. Its temporary facade retains immutable admission metadata and projects actual scalar facts from the still-unmigrated legacy executor. Its initial attempt reference is not a completed migration of continuation/attempt history. File history still lives in the legacy aggregate; paging that projection does not make the File store indexed or bounded.

Public queue/cancel events contain bounded state and immutable captured inputs. The optional File admission view contains allowlisted presentation summaries from the same committed ledger/state; SQL queue omits this view and creates no accounting observation or invented zero. Client cancellation merges lifecycle state without replacing displayed worker messages, commands or checks. No acceptance evidence is generated by queue/cancel.
