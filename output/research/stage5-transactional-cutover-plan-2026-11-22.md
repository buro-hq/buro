# Stage 5: transactional state, paged history and optional quotas

Date: 2026-11-22. Read-only plan against the working 4C3a tree, following committed 4C2 (`b7a5c70`). This is proposed implementation, not a claim of SQLite adoption or unrestricted-duration execution. Current finite ceilings remain active until 5C passes. No user state was migrated, no original repository was changed, and no model, credential or RTX endpoint was accessed.

Prerequisites: finish 4C3a role templates and 4C3b empty configured resources with their own tests/reviews/commits. Preserve the operation, material, role provenance, immutable verification and unknown-effect invariants established in stages 1–4. The prior [quota design](optional-quota-migration-2026-11-21.md) remains the policy decision; the older [persistence audit](persistence-policy-audit-2026-11-21.md) identifies defects but some line numbers and findings are historical. In particular, result application already has prepare/dispatch receipts in `core/project-application.ts` and must retain those rather than reimplement the original unjournaled apply.

## What must change together

`core/ports.ts` still exposes a mutable whole `ProjectDocument`; 21 direct transaction call sites span `core/{services,execution,project-application,project-research,results}.ts` and `adapters/files/{context-materials,project-run-budgets}.ts`. `FileProjectStore.transact` clones live collections, validates every ledger/history invariant, scans old events, then rewrites all state/history. `core/run-budget.ts` recounts the entire operations map. `ManagedSessionStore.load/save` similarly serializes messages, actions, turn authorities, scope revisions, check entries and all archives. Moving these same growing objects into one SQL JSON column would preserve the problem.

The replacement is a transaction over specifically loaded entities plus narrow append/settle operations. Historical data is indexed and paged. Complete private evidence is retained separately from a bounded active model context and bounded UI projection. Public projection, private journal, usage delta, policy revision and command receipt share the owning database transaction; publication follows commit.

## Database ownership and the smallest useful ports

Use one private local SQLite database per project authority and one private SQLite database for machine configuration. The `ProjectStoreFactory` storage address stays opaque to Core; the default adapter maps it to the project database. Production must not also write authoritative `control-state.json`, managed session JSON, route JSON or a JSON budget ledger for new-format records. JSON entity payload columns are fine for bounded current records; they are not a place for unbounded history arrays.

The project database owns project/profile revisions, goal entities, immutable role versions, runs/current workflow state, assignment and operation grants, research/preparation operations, native/managed route handles, session headers, effect receipts, usage accounts/operations, command receipts, public event sequence, artifact manifests and references. Immutable artifacts may be chunked BLOB rows in this same database. Start with that implementation for private messages/results/continuations: it avoids introducing another file-commit protocol. Existing content-addressed material bytes may remain external immutable files; their metadata/reference authority moves into SQLite.

The machine database owns linked-project definitions/connection receipts and resource connection/runtime/profile configuration, revisions and configuration command receipts. Credential values remain private credential-provider inputs, never public config rows or exported receipts. A machine policy is copied into a project run's resolved policy snapshot before admission. No cross-database transaction or exact cross-project spending cap is claimed. Diagnostic probes without a project get an explicit machine-owned operation, rather than inventing a run owner. Each effect has exactly one owning authority.

Recommended interfaces, in `core/project-state.ts`, `core/execution-journal.ts`, `core/usage-accounting.ts` and `core/artifacts.ts`:

- `ProjectState.readProject()`, `goal(id)`, `run(id)`, `latestRole(id)`, and indexed `listGoals/listRuns/listRoles/listMaterials(page)` return detached data. `run(id)` returns bounded current state, not every timeline entry/session/attempt.
- `ProjectState.transact(command, apply)` supplies a synchronous typed `ProjectTransaction`, with typed read/save methods for the particular goal/run/profile/role/research/result operation, an `appendEvent` method and receipt handling. No Node, raw SQL or external async work enters the callback. Expected entity revisions are checked inside the transaction. Queries inside the callback use the same transaction snapshot.
- `ExecutionJournal` atomically admits a generation or complete tool batch with original scope/tool/resource grant and usage decision; records the canonical response before any tool dispatch; and settles one generation/action/check/helper command by original ID. The journal binds public run deltas and session state changes to the same transaction. Separate wrappers may expose these ports, but all are views of the same `ProjectAuthority`, not independent stores.
- `UsageAccounting` receives one account summary, resolved policy and the specific prior operation receipt. Pure Core functions return a decision and counter delta. Indexed inserts/updates commit the operation plus summary plus owning public projection. No `SELECT all operations`, full ledger validation or reconstruction of `Record<id,operation>` occurs on the hot path.
- `SessionHistory` exposes current header/active-context page, indexed message/action/check/segment append and cursor-based private reads. Scope grants and private continuation references remain version-bound; a caller cannot change them with a patch.
- `ArtifactStore` stages immutable chunks, verifies a final digest and links a finalized manifest from the owning transaction. Only committed references grant read authority. Partial staged chunks can be collected later; committed missing/corrupt content blocks recovery.

These are storage capabilities, not another scheduler. Core still chooses operations and checks. Provider/backend/tool contributions cannot acquire a competing journal or directly mutate SQL. Root composition passes the same project authority to runtime routing, managed host effects and application services. A small factory-owned project lookup can resolve a session's owning project without loading all sessions into memory; handles carry an opaque indexed owner binding, never arbitrary client-supplied database paths.

Use `node:sqlite` behind `adapters/sqlite/` only. Prepared statements, foreign keys, unique owner/operation and command keys, `BEGIN IMMEDIATE`, WAL and `synchronous=FULL` are the starting local policy. Keep transactions short and never await a model/process within one. Initial `DatabaseSync` transactions are acceptable if measured bounded; a worker can later own the same adapter if synchronous latency needs isolation. SQL access belongs to the adapter, not Core or UI.

SQLite write serialization alone does not prevent two daemons from dispatching the same external effect. Keep a durable service/dispatch owner nonce and checked owner lease. Takeover requires verified owner termination or explicit reconciliation; elapsed heartbeat time alone grants no replay. A pending/unknown generation, native start, command, deployment or Git mutation never becomes safe merely because a lock disappeared. Replace the current stranded `.recovery` file guard rather than copying that algorithm into the SQL adapter.

## 5A: one authority and incremental accounting

Implement and commit in reviewable slices:

1. Add versioned entity/journal/accounting contracts and pure incremental decision functions. Define owner variants for run work, research and result preparation; operational preparation must not poison a completed coding Run with an implementation reconciliation marker. Preserve existing frozen role/resource/tool/context identity validators as touched-record validators. Add accounting transition tests before wiring storage.
2. Implement `SqliteProjectAuthority` and factory with prepared schema/transaction/receipt/event primitives. Tables separate current entities from append-only events, sessions, effect receipts, usage operations and artifacts. Prove atomic rollback, uniqueness, foreign-key ownership and reopen before production wiring. Avoid a transitional SQL sidecar to a live JSON project.
3. Migrate the actual application call sites to typed entity transactions. This includes idempotent goal/role edits, run start/change/continuation, analysis admission, result preparation, result application and material metadata. Replace full-document `snapshot().runs/goals` admission scans with indexed queries. A temporary bounded UI projection can exist until 5B, but it is explicitly a query/cache over SQL and cannot grant authority or silently omit a run used by admission.
4. Move managed session headers, native routes, generation/action/service-check receipts and accounting into that same authority. Replace `ProjectRunBudgets` with `ProjectUsageAccounting`; keep finite resolved policies during 5A. Preserve complete normalized provider response before usage settlement and before proposed tools. Persist the whole admitted tool batch before its first dispatch. A per-helper command gets its own child receipt and start/completion/unknown outcome; aggregate tool results no longer stand in for every command.
5. Give analysis/result preparation durable owning operation IDs and pending/completed/unknown state before runtime start. Reopening an unknown preparation offers reconciliation/new explicitly identified attempt; it never repeats silently, changes accepted implementation grants or retroactively calls an unreviewed result accepted.
6. Replace machine configuration's instance-local read/check/rename CAS with transactional revision + receipt CAS. Resource notifications publish after successful commit only. Repository `project.json` is an export/import proposal; equal-revision different content cannot replace authoritative state. Add a separate validated import command rather than a fallback merge at open.

5A acceptance: current functional suites against SQL adapters; failed reserve/write publishes nothing; reserve + effect intent + summary + event + receipt agree after every crash boundary. Duplicate request returns its original result; different fingerprint conflicts. A canonical terminal response retained before settlement remains recoverable after a settlement failure without a second provider call. Pending/unknown writes remain blocked; cleanup keeps original runtime lease identity after registry revocation. Finite quotas continue to work while no-quota defaults remain unreleased.

## 5B: paged public/private history and complete artifacts

Replace `ManagedSession`'s growing arrays in `core/model-ports.ts` and the whole-file `FileManagedSessions` transition mechanism with bounded active state and indexed journal/history queries. Required consumers are `core/{managed-runtime,managed-loop-host,managed-host-effects,managed-coding-context,managed-worker-checks,managed-session-authority}.ts`. Unknown-effect checks query unsettled rows by owner/session, not all historical actions. Recent handoff receipts are a bounded context projection with IDs/links to complete private receipts; history is never deleted to make the prompt fit.

A segment close atomically seals the previous context manifest, appends its complete messages/continuation/evidence references, changes the active segment and installs the next active context. It cannot reset lifetime usage or replace the original task, scope, check profile or model authority. Context threshold and short tool windows remain scheduling choices; total archive count becomes a paged index. Required original task/criteria must be preserved exactly in a durable packet; if one request cannot contain them, retrieval/partition is explicit and omission never becomes an invented fulfilled criterion.

Store full generation inputs/responses, tool/helper outputs, step-check outputs and research packets privately before making their bounded public excerpts. Present truncation as an excerpt with artifact identity and a retrieval path; do not claim the current tool adapter's already-truncated string is the original complete process output. Capture stdout/stderr streams at their execution boundary before producing tails. Binary/large artifacts use chunks, never a complete growing SQL JSON map.

Break public `Run` timeline/commands/attempts/session history out of `protocol/domain.ts`. Add cursor pages to `protocol/schema.ts`, `plugins/{host,execution,project-operations,local-files}.ts`, `daemon/websocket.ts`, `clients/{project-client,socket-client,replay-client}.ts`, `plugins/local-files.ts` and the inspector/playback/goal/material UI. Use keyset cursors `(project sequence or entity sequence, id)` tied to a query/filter/watermark, not offset pagination. Initial selection returns a bounded project overview and snapshot sequence. Replay loads pages up to a captured watermark, installs/buffers live events without a gap, then drains in order. A page-size maximum is not a lifetime maximum. Old cursors cannot mix project A/B or changed filters.

Move current research event truncation (`core/project-research.ts`, 40 entries) to a complete journal plus bounded live preview. Page context material navigation instead of `context.list` returning the whole library. Resolve dedup/reactivation inside the authoritative import transaction after byte preparation; the returned record/event must match the committed active state during import/remove interleavings. Keep immutable material grants readable after library removal. Reference-aware collection covers runs, research, sessions and retained result packets, not only active navigation. Staged/orphan material blobs require a grace period and live preparation lease before collection.

5B acceptance: >15 segments and thousands of messages/tool results remain privately retrievable with exact order/hash/continuation; active context stays bounded. >1000 historical attachments and removed-but-referenced materials do not lose bytes. UI/CLI paginate many goals/runs/history without downloading every detail, with exact replay/live ordering and A→B stale-response guards retained. Read memory and bytes written per append do not scale with total history. Complete private payloads never enter ordinary public events, provider logs or resource catalogs.

## 5C: default-none policy and every hidden stop

Only activate this after 5A/5B gates. Replace the old budget schemas/API entirely; prerelease compatibility is unnecessary. Missing override means inherit; root resolves to `none`; explicit `none` clears inherited caps; `bounded` contains only the user's selected finite dimensions. Snapshot policy source/revision and enforcement coverage at run admission. Updating policy is a CAS/idempotent command that appends a new revision and preserves all usage/receipt history. A known-before-dispatch quota pause can continue after editing policy; unknown effects still require reconciliation.

Track historical admitted request/output allowance, known observed usage and outstanding reservation exposure separately. For optional token quotas, settle observed known usage and release unused exposure; unknown outcomes keep conservative exposure until reconciled. Partial/absent native usage is unknown, never zero. Exact whole-run provider request/spend caps are unavailable for opaque native clients: expose coverage and reject unsupported precision rather than count one native turn as one model API call. Review reserve exists only within an explicitly bounded envelope.

## Clean prerelease activation

Do not run this procedure on user data as part of planning/tests. Implement/test it on Buro-owned synthetic roots first. User repositories, their Git metadata, credentials and the RTX machine stay untouched.

1. Drain admissions/jobs/process leases, refuse activation while an owner is live, and acquire the verified service owner. Old pending effects remain archived unknown; no migration dispatches them.
2. Prepare a new-format authority in a new Buro-owned directory. Validate schema and private permissions, fsync/close the database and any external immutable staged artifacts, then atomically switch a small storage-location manifest. The manifest selects the authority; it does not duplicate run/config truth. Crash before switch leaves old selection; crash after switch opens only the complete new authority. Never partially merge old/new execution rows.
3. Preserve old files byte-for-byte as non-executable archive input with a manifest/hash and no deletion. No old runtime route/session/budget parser is consulted by the new recovery path; no old acceptance or usage is invented. Archive browsing may use static reports/raw files, not old executable service objects.
4. Optional import is a separate explicit operation for selected project definitions, goal intent and material bytes only, validated into new IDs and reviewed settings. It cannot import old effects, threads, acceptance, checks-as-proof, accounting receipts, finite hidden defaults or secrets. Source profile export remains an explicit later write, never part of activation. Existing user state is not silently migrated.

## Failure, scale and boundary gates

- Kill synthetic child processes before/after admission, response preservation, usage settlement, action/helper start, mutation completion, command/event/receipt commit and postcommit publication. Reopen must recover exactly one authoritative outcome and never dispatch a recorded unknown effect again.
- Two actual independent processes opening the same project/config authority must not both acknowledge a lost update. Test expected-revision conflict, duplicate receipts and owner death at every takeover step. `BEGIN IMMEDIATE` alone is not the dispatch ownership proof.
- Force rollback, disk-full/I/O error, invalid usage, corrupted/missing artifact/chunk, interrupted staging, canceled late native start and failed cleanup. A committed reference must resolve and validate; an orphan never grants access. Rejected observer callbacks cannot roll back committed state.
- Assert the same immutable tree/role/resource/tool/context/policy grant is checked, reviewed and committed after SQL transition. Native and managed adapters face identical capability/authority rules; no brand-specific fallback appears.
- Instrument statement/row reads and retained memory at 1K, 10K and >17408 operations. One admission/settlement loads a constant number of owner/summary/receipt rows; no hot-path `SELECT *` over history or full JSON rewrite. Wall-clock measurements supplement this deterministic work-bound assertion rather than replace it.
- No-quota synthetic runs cross every former 24/64/256 request/action limit, >4/15 windows, >2 failed feedback cycles and >1000 material history records. Verify counters/continuations survive restart and no lifetime quota stops them. Explicit finite quota tests include inheritance→none, none→bounded, lowered cap with existing exposure, duplicate completion, unknown usage and review allowance only when configured.
- Test old activation archives cannot reach new runtime resume, result acceptance or effect dispatch. All synthetic source repositories are disposable. Actual model comparisons remain later controlled tests using local Mac Ollama and DeepSeek only; no RTX access.

Each numbered slice receives focused tests, full relevant checks, architecture/code/boundary review, a separate commit and a short report. Do not enable default-none at 5A just because SQLite exists. 5C completion requires storage/paging consumers and the hidden-stop audit to pass together.

## Local feasibility evidence

A disposable probe in the system temporary directory used installed Node `v24.9.0`, built-in `node:sqlite`, SQLite `3.50.4`, WAL and `synchronous=FULL`. A second connection's competing `BEGIN IMMEDIATE` failed with SQLite error code 5 (`database is locked`); after the first commit, that connection read the committed receipt. Both connections were closed and the temporary directory removed. Node emitted its experimental SQLite warning. This proves local primitive availability only, not production crash durability, owner leases, application transaction correctness or performance. No dependency install/network call was needed.
